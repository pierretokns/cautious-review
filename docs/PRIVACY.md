# Privacy — 0.3.0 preview

Candidate text, local review decisions, and local semantic-search inputs stay in the extension. There is no hosted model, telemetry, analytics, or candidate-data server. The bundled MiniLM model runs in browser WASM, with remote model loading disabled. PDF.js, its worker, and model assets are packaged locally; PDF parsing can use installed system fonts.

Live Review uses Harvest v3 and can download résumé files from the listed Greenhouse document-storage hosts. A separate local Node helper sends the OAuth client ID and secret to `auth.greenhouse.io` to mint a short-lived bearer token; it prompts for the secret without showing it, asks before printing the token, and stores neither credentials nor token. It sends no candidate data. The token is then pasted into Live Review and remains only in that page's memory until disconnect or page close; it is not persisted in extension storage or exposed to Greenhouse page scripts. Greenhouse's guide recommends server-side storage for credentials and tokens; this local helper is a user-operated convenience, not a managed server-side credential broker. The extension contacts only the fixed Harvest API origin and approved Greenhouse document-storage hosts. HTTPS requests omit ambient browser credentials, reject redirects, and have bounded response sizes and timeouts.

The supported account hosts are the five listed US Greenhouse app hosts and `app.eu.greenhouse.io`. Custom SSO subdomains are not granted access. The extension does not scan résumé HTML, arbitrary hidden fields, page globals, or applicant text for identifiers. It reads identifiers only from recognized same-origin Greenhouse action forms and selected navigation, then verifies them with Harvest before displaying a record or preparing an action.

Selected, pasted, imported, or retrieved résumé text and local decisions are stored in extension-origin IndexedDB. The content-script database uses seven-day cleanup when the extension next performs cleanup; Live Review résumé records use that same store. Live write receipts use a separate local database and persist until the user clears them. **Clear all local data** clears both stores. These data are not application-encrypted, and clearing browser history is not a reliable way to remove extension storage. Use a separate Chrome profile or clear local data before switching accounts on the same Greenhouse origin.

Retrieved documents are capped at 20 MB; extracted text is capped at 200,000 characters. PDF parsing, local model inference, and lexical/alias fallback run in the browser. Search results show passages and retrieval information. Similarity is not a candidate score and does not create a disposition.

The numeric user ID is passed as OAuth `sub` and verified as an active Greenhouse user before use. Greenhouse requires a Site Admin authorizing user for list endpoints. Configure only the endpoint permissions for the intended reads and reviewed actions in the Harvest V3 OAuth credential. Organization-configured Greenhouse automations may run after a write; Cautious Review does not request a rejection email.

Browser fixtures use synthetic records and documents. They are not real-account end-to-end validation. Do not commit applicant documents, receipts, credentials, signing keys, or browser profiles to this public repository. Greenhouse is the system of record; local retention and receipts are not a substitute for required HR recordkeeping.
