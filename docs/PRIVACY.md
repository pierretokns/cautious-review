# Privacy — 0.3.3 preview

Candidate text, local review decisions, and local semantic-search inputs stay in the extension. There is no hosted model, telemetry, analytics, or candidate-data server. The bundled MiniLM model runs in browser WASM, with remote model loading disabled. PDF.js, its worker, and model assets are packaged locally; PDF parsing can use installed system fonts.

The optional Live Review integration uses Harvest v3 and can download résumé files from the listed Greenhouse document-storage hosts. A separate local Node helper sends the OAuth client ID and secret to `auth.greenhouse.io` to mint a short-lived bearer token; it prompts for the secret without showing it, asks before printing the token, and stores neither credentials nor token. It sends no candidate data. The token is then pasted into Live Review and remains only in that page's memory until disconnect or page close; it is not persisted in extension storage or exposed to Greenhouse page scripts. Greenhouse's guide recommends server-side storage for credentials and tokens; this local helper is a user-operated convenience, not a managed server-side credential broker. The extension's Harvest requests use the fixed Harvest API origin and approved Greenhouse document-storage hosts, omit ambient browser credentials, reject redirects, and have bounded response sizes and timeouts.

## Page-linked résumé reading

The **Read this résumé locally · no admin key** button appears on supported Greenhouse candidate pages. After the reviewer clicks it, the content script requires one unambiguous candidate and application identity from the current route/selected navigation and exactly one visible résumé or CV attachment link/control. It sends one same-origin HTTPS `GET /attachment_previews/{attachmentId}?width=800` request with the browser's existing Greenhouse session credentials, bounded to 20 seconds and one megabyte. It does not read candidate records through a general session API, enumerate attachments, or send a candidate write. The response must be successful JSON and resolve to HTTPS on an approved Greenhouse résumé-storage host. Redirects are rejected. Before opening the reader, the extension compares the page-reported URL with the browser's current tab URL and rechecks that the page, application context, and attachment are still the same. This also detects single-page navigation that leaves the original document alive. The signed document URL has a shared 16 KB size limit and is held only in the one-use memory handoff; it does not independently verify that the attachment belongs to the displayed application.

The signed document URL is not placed in the reader tab URL or extension storage. The extension service worker holds it with the page-derived candidate/application IDs in memory behind a random one-use reader handoff; the handoff expires after 90 seconds and is consumed when the local reader asks for it. The reader labels these IDs as coming from the page, not independently verified by Harvest, and warns that a résumé may be attached to the candidate profile rather than the displayed application. The reviewer must confirm it is the résumé version relevant to the application before using its evidence. The reader requires an explicit trusted click to download the document. That cross-origin download sends no browser credentials and no referrer, rejects redirects, and accepts only the approved Greenhouse S3 hostnames. PDF parsing, text extraction, analysis, and local search run in the extension. Extracted text is saved in extension-origin IndexedDB under the same seven-day cleanup behavior as other résumé records. The signed URL and downloaded file bytes are not persisted by the reader.

The extension's finite host grant covers `app.greenhouse.io`, `app2.greenhouse.io` through `app15.greenhouse.io`, and `app.eu.greenhouse.io`. It is used for page scripts and to confirm the current tab URL during the reader handoff; there is no global tabs permission. The extension does not request wildcard Greenhouse access or customer-specific domains. Greenhouse's public guidance describes numbered `app[#].greenhouse.io` accounts and includes `app15.greenhouse.io` as an example ([extension setup](https://support.greenhouse.io/hc/en-us/articles/8302339682843-Install-the-Greenhouse-Recruiting-Chrome-extension), [TextUs integration](https://support.greenhouse.io/hc/en-us/articles/360017515752-TextUs-integration)). Other shards and custom SSO domains are not granted access, and the account experience on each included host has not been validated. The extension does not scan résumé HTML, arbitrary hidden fields, page globals, or applicant text for identifiers. Page-linked reading uses only supported route identities, a unique selected navigation link, and a visible résumé attachment control; no text inside an embedded résumé is inspected to discover IDs. Harvest-backed records/actions continue to use their own identity checks.

Selected, pasted, imported, or retrieved résumé text and local decisions are stored in extension-origin IndexedDB. Records expire after seven days and are deleted when the extension next performs cleanup, including on Live Review operations and page-linked reader load/search. Live write receipts use a separate local database and persist until the user clears them. **Clear all local data** clears both stores. These data are not application-encrypted, and clearing browser history is not a reliable way to remove extension storage. Use a separate Chrome profile or clear local data before switching accounts on the same Greenhouse origin.

Retrieved documents are capped at 20 MB; extracted text is capped at 200,000 characters. PDF parsing, local model inference, and lexical/alias fallback run in the browser. Search results show passages and retrieval information. Similarity is not a candidate score and does not create a disposition.

The numeric user ID is passed as OAuth `sub` and verified as an active Greenhouse user before use. Greenhouse requires a Site Admin authorizing user for list endpoints. Configure only the endpoint permissions for the intended reads and reviewed actions in the Harvest V3 OAuth credential. Organization-configured Greenhouse automations may run after a write; Cautious Review does not request a rejection email.

Browser fixtures use synthetic records and documents. They are not real-account end-to-end validation. In particular, the private page-linked preview route has not been confirmed against an authenticated Greenhouse account; public-source inspection only identifies plausible behavior. Do not commit applicant documents, receipts, credentials, signing keys, or browser profiles to this public repository. Greenhouse is the system of record; local retention and receipts are not a substitute for required HR recordkeeping.

## Opt-in browser-session diagnostics

The preview includes a passive observer to help map Greenhouse's browser-session request shapes. Recording is off until the reviewer explicitly starts it. While on, it observes same-origin HTTPS JSON fetch/XHR traffic from normal page activity, passes the original calls and results through unchanged, and does not create network requests or invoke candidate actions. The sanitized observations contain request methods, redacted path templates, allowlisted query-key names, allowlisted request and response schema key names and value types, and HTTP status codes. Bounded JSON bodies are converted immediately to canonical schema summaries; raw bodies and scalar values are not retained or exported. Cookies, tokens, authorization values, and other header values are not captured. Treat schema observations as untrusted hints, not a stable or verified API contract.

Observations exist only in the current page's memory, up to 100 records or ten minutes. Stopping retains the sanitized buffer for manual export; clearing deletes it. Export is an explicit local file download named `cautious-review-session-diagnostics.json`. Reloading or closing the page discards the buffer. Review the exported file before sharing it; this is not an automatic upload or telemetry channel.

The preview's browser-session path reads one explicitly linked résumé attachment only. It does not provide general session-backed application listing or candidate actions. The observed preview route is private and has not been validated with the user's account; synthetic fixtures and public-source observations do not establish production compatibility. The optional Harvest integration described above still requires its configured permissions and a Site Admin authorizing user for list endpoints and remains the route for reviewed Greenhouse actions.
